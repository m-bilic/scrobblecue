# ScrobbleCue

ScrobbleCue logs vinyl records you play to [Last.fm](https://www.last.fm) ("scrobbling"), using your [Discogs](https://www.discogs.com) collection as the source of release and track data.

It consists of a stateless backend API, an Android app and a website. An iOS app is planned. There are no ScrobbleCue accounts, and the server stores no user data.

## Status

Early development. There is no working code or release yet. The roadmap is described in [docs/PLAN.md](docs/PLAN.md), and the technical design in [docs/SPEC.md](docs/SPEC.md).

## How it works

1. You connect your Last.fm and Discogs accounts. Your access tokens are stored encrypted on your device.
2. Your Discogs collection is loaded and cached on your device.
3. When you open a record, its tracklist is fetched from Discogs and grouped by vinyl side (A1, B2, …).
4. You scrobble a side, the whole record, or selected tracks.
5. The backend signs the request with the app's API secret and forwards it to Last.fm, with timestamps based on track lengths. It keeps nothing.

## Planned features

- Browse and search your Discogs collection
- Scrobble a single side, a whole record, or selected tracks
- Live mode: scrobble tracks as they finish playing, with a reminder to flip the record
- Recently played (from Last.fm), most played and not played in a while (from the device)
- Metadata cleanup (e.g. Discogs artist suffixes like `Artist (2)`) and missing track durations filled from MusicBrainz
- Per-track corrections, stored on the device and reused on later plays
- Offline queue
- Later: barcode scanning, Android home-screen widget and Quick Settings tile, iOS app

## Architecture

```
Android app ─┐                                     ┌─► Last.fm API
Website ─────┼──► Backend (stateless REST API) ────┤
iOS app ─────┘                                     └─► Discogs API (login, collection)
      │
      └──► Discogs API (public tracklists), MusicBrainz API (track lengths)
```

The backend holds the app's API secrets and signs and forwards requests. It has no database. User tokens, the collection, corrections and the play log are stored on the user's device. API clients are generated from the backend's OpenAPI specification.

## Usage

Once released, ScrobbleCue will be available on Google Play and at scrobblecue.app. Users connect Last.fm and Discogs; no account, server or API keys are required.

## Running locally (development)

Requirements: JDK 25, Node.js 24.

1. Copy `.env.example` to `.env` in the repository root and fill in your own [Last.fm API account](https://www.last.fm/api/account/create) and [Discogs application](https://www.discogs.com/settings/developers) keys. Generate a sealing key with `openssl rand -base64 32` and set `CREDENTIAL_KEYS=k1:<key>`. `.env` is git-ignored.
2. Start the backend:

   ```
   cd backend
   ./gradlew bootRun
   ```

3. Check that it runs:
   - http://localhost:8080/v1/meta – API version
   - http://localhost:8080/actuator/health – health check
   - http://localhost:8080/swagger-ui – API documentation

4. Start the website (the dev server forwards `/v1` to the backend on port 8080):

   ```
   cd web
   npm install
   npm run dev
   ```

   Open http://localhost:5173. The defaults in `.env.example` (`PUBLIC_BASE_URL`, `WEB_BASE_URL`) already point sign-in back to these local addresses.

Tests:
- Backend: `./gradlew build` in `backend/` (also regenerates `api/openapi.json`).
- Website: `npm run typecheck`, `npm test` and `npm run build` in `web/`. After an API change, `npm run gen:api` regenerates the TypeScript types from `api/openapi.json`.

The Android app will be added in a later phase.
